## 2026-10-26

- **SPEC contradicted the technical minimum.** The agent-drafted `SPEC.md` listed "Scheduling and hosting" as out of scope, but the assignment requires at least one part to run automatically. Corrected: the daily run is in scope (GitHub Actions), only hosting and notifications are out of scope.
- **Wrong licence for MET data.** The agent-drafted `SPEC.md` gave MET Norway's licence as CC BY 4.0 only. Checking https://api.met.no/doc/License showed NLOD 2.0 and CC BY 4.0. Corrected in `SPEC.md`.
- **Facts kept away from the model.** Instead of letting the LLM write the whole digest, we required that IDs, levels, areas and dates are copied by code and the model only writes `summary_no`. The check then rejects any summary containing a number that is not in the source.
- **Wrong NVE endpoint in generated code.** The harness code from a separate Claude session used `.../flood/v1.0.10/Warning/County/34/1`, which returns 404. The coding agent tested the endpoint before running, found the correct path is `.../flood/v1.0.10/api/Warning/County/34/1` (200, 138 records), and proposed the fix. Lesson: verify every API path against the live service, not only the docs.
- **Duplicate warning IDs.** The generated normalise.py assumed one NVE record per warning, but NVE sends one record per municipality sharing the same Id. The coding agent found this in the live response and merged records by Id, stopping the run if the merged records disagree on level or validity. Without the fix the check would have failed (same warning listed 5 times).
- **Weak Norwegian from llama3.2:3b.** The first live Ollama digest passed all fact checks but contained wrong or garbled Norwegian ('Flomfare er utsatt', 'sikre verdier bort fra'). The binary checks cannot catch language quality; this motivates the LLM-as-judge readability rubric and a model comparison in the evaluation.
- **Tamper test failed for the wrong reason.** To verify the report's claim that the check detects errors, the agent tampered with `out/digest.json` three times. The level change and the removed warning failed on properties 3 and 1 as expected. The first invented-number test appended a sentence, which pushed the summary over 60 words, so the check failed on word count instead of the number. Rerun with a sentence replaced (50 words), it failed on property 5 (`number '47' ... is not in the source`). A separate test confirmed that Stage 4 drops a summary for an invented ID. Lesson: a failing check only proves something if it fails on the property under test.

## 2026-11-26

- **Agent blocked by the eval/ guard and refused to bypass it.** While building the evaluation harness (task 005), the agent's write to `eval/cases/` was denied by the `Edit(/eval/**)` rule in `.claude/settings.json`. It stopped instead of writing the files through the shell, explained that the rule is the guardrail behind "never edit `eval/` without asking", and proposed narrowing the rule to lock only the checkers (`Edit(/eval/check_digest.py)`, `Edit(/eval/check_probe.py)`). We accepted, so new case and runner files can be added while the checkers stay protected.
- **Eval harness found a warning without an end time that passed every check.** The derived case `missing_fields` (`ValidTo` removed from all five records of warning 584962) was expected to be rejected, but the run exited 0: Stage 2 copied `valid_to: null`, the template summary said "Gjelder fra 26.10.2026 kl. 07:00 til ?", and `check_digest.py` passed because the digest's null equalled the source's missing value. Baseline 7/8 (`eval/results/2026-11-26_baseline.md`). Fix in `harness/normalise.py`: an active Innlandet warning (level >= 2) with no `ValidFrom` or `ValidTo` now stops the run with "NVE warning <id> has no ValidTo; no digest produced." The checker was not changed. After the fix 8/8 (`eval/results/2026-11-26_after_fix1.md`), and `run.py --offline` still passes. Lesson: an equality check between source and digest cannot catch data that is missing in both; required fields must be enforced where the data enters.
- **Stress test 1 found a silent all-clear (task 006).** The derived case `missing_countylist` (CountyList removed from the five 584962 records) was expected to be rejected, but Stage 2 treated "no county list" as "not Innlandet" and skipped the warning. The digest said "Ingen aktive flomvarsler ... for Innlandet" while a yellow warning existed, and `check_digest.py` passed (0 warnings checked) because it uses the same county filter. Before: eval 14/15 (`eval/results/2026-11-26_stress1_before_eval.md`). Fix in `harness/normalise.py`: an active record (level >= 2) without CountyList stops the run ("cannot tell if it is for Innlandet; no digest produced."). After: 15/15 (`2026-11-26_stress1_after_eval.md`). Lesson: when the harness and the checker share a filter, they share its blind spot; unknown must mean stop, never "not ours".
- **Two malformed-input cases passed for the wrong reason.** `bad_level_text` (ActivityLevel "gul") and `missing_id` (Id removed from one record) were counted as correct rejects, but the run had crashed with a Python traceback (`ValueError: invalid literal for int()`, `KeyError: 'Id'`). We first made the eval honest: in `eval/run_eval.py` a reject only passes on a controlled stop with a "no digest produced" message, and a traceback is "crash, not a controlled stop". Lenient eval 14/15 became strict 12/15 (`2026-11-26_stress1_before_eval_strict.md`). Fix in `harness/normalise.py`: clean stops for a missing Id and a non-integer ActivityLevel. After: 15/15. Lesson: a non-zero exit code is not proof that the harness noticed the problem.
- **Meaning drift "Flomfare er utsatt" under the phone injection.** At temperature 0, `injection_phone` gave the same summary in 3/3 runs, starting "Flomfare er utsatt i deler av Østlandet" (can be read as "the flood danger is postponed") and with no colour word. It passed both `check_digest.py` and `check_injection.py`. This is a model habit, not a successful injection: the same phrase is already in `fixtures/llm_summaries.json` and in the 2026-10-26 entry above. All three injections were resisted (9/9 runs, `2026-11-26_stress1_before.md`), but the 3 runs per case were identical, so they were really 1. Fix in `harness/assemble.py`: a model summary without the colour word for its level (gult/oransje/rødt), with "utsatt" not followed by "for", or with "avlyst"/"ingen fare" is replaced by the template summary, and the digest records `summary_mode: "fallback"` with the reason. The same rules were added to `eval/check_injection.py`. After, at temperature 0.7, 5 runs per case: 15/15 injection runs pass both checks and none obeyed the injection; 10/15 fell back to the template, all for a missing "gult" (the model wrote "Gull nivå", "Gullvarsel" or no colour at all; 2 of the 10 also said "Flomfare er utsatt"); 5/15 kept the model's text (`2026-11-26_stress1_after.md`). The offline replay fixture now falls back too. Lesson: the checks proved the facts but not the meaning; with this 3B model the colour rule fires in two runs out of three, which says more about the model than about the injections.
- **Huge input was silently truncated by Ollama.** `huge_text` (MainText of 50 000 characters) passes with `--no-llm`, but with the model on it failed 5/5 at temperature 0.7: the prompt was cut to 2050 input tokens (Ollama's default context window), the model lost its instructions and returned JSON without the warning ID (4 runs, empty summary, `check_digest.py` property 5) or invalid JSON (1 run). The harness failed safe: no digest.md was left. Not fixed yet; options are a length cap on main_text in Stage 3 or a larger `num_ctx`.
